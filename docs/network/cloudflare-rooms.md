# Комнаты на Cloudflare: первая версия

Проверено 30 октября 2026 года: в панели аккаунта для Workers выбран **Free**. Настройки подписки не менялись. Прямого деплоя из локальной среды не было.

## Возможности и лимиты

SQLite-backed Durable Objects доступны на Workers Free. Один объект координирует одну комнату; два WebSocket-клиента получают подтверждённую сервером позицию. Используется Hibernation API (`ctx.acceptWebSocket`), без серверных интервалов. Клиентский ping/pong обрабатывается через `setWebSocketAutoResponse`.

Лимиты Free по официальной документации на дату проверки:

- Workers: 100 000 запросов в сутки, 10 мс CPU на вызов.
- Durable Objects: 100 000 учитываемых запросов в сутки, 13 000 GB-s активного времени в сутки.
- SQLite для DO: 5 млн прочитанных и 100 000 записанных строк в сутки, 5 ГБ суммарного хранения.
- Для учёта запросов входящие WebSocket-сообщения считаются 20:1; исходящие сообщения не тарифицируются как запросы. Подключение требует отдельного запроса.
- При исчерпании бесплатного лимита соответствующие операции начинают возвращать ошибки; автоматического перехода на платный план нет. Лимиты аккаунта разделяются с другими проектами.

Это подходящая стартовая архитектура для пошаговой игры, но число одновременно обслуживаемых партий нужно оценивать по фактической нагрузке. Дополнительные D1, R2, отдельный VPS и mctl для этого режима не нужны. Статические ресурсы идут через Workers Static Assets, Worker-first маршрутизация ограничена `/api/rooms` и `/api/rooms/*`.

## Область первой версии

- Лобби → создать комнату с выбранными правилами → поделиться ссылкой → второй игрок автоматически занимает свободное место при открытии приглашения. Сохранённый ключ возвращает игрока на его прежнее место; заполненная комната не выдаёт новых мест.
- Пока второе место свободно, доска размыта: «Ожидаем игрока» и «Посмотреть доску». Просмотр снимает размытие, но ходы доступны только после присоединения друга. Кнопка приглашения исчезает после занятия второго места и не возвращается при временном отключении игрока.
- Создатель — жёлтые, второй игрок — красные. Первый ход жёлтых. Каждому все портреты обращены к нему; красный игрок видит перевёрнутую доску.
- Регистрации, чата, каталога, паролей, часов и зрительских подключений нет. Оба занятых места не позволяют третьему игроку сесть за доску.
- Пароль и публичный каталог — отдельный будущий этап. Ссылка на комнату не содержит личного ключа места.
- Сервер выдаёт случайный ключ места; браузер хранит его отдельно по комнате. В объекте хранится только SHA-256 ключа. WebSocket подтверждает место первым auth-сообщением; ключ не попадает в URL.
- При перезагрузке того же браузера используется то же место. Новая вкладка с тем же ключом заменяет старое подключение. После удаления данных браузера автоматическое восстановление места невозможно.
- Общий движок проверяет ход на сервере. Клиент не изменяет позицию оптимистически. Монотонная revision отклоняет устаревшие действия.
- Отмена откатывает собственный последний ход инициатора и все ответы после него, по согласию соперника. Новая партия тоже требует согласия, сохраняет стороны и снимок правил. Сдаться можно самостоятельно.
- Комната и её текущая партия хранятся на сервере до 7 дней без игровых действий. Продление срока — при входе второго игрока и принятом действии, не при heartbeat. Alarm удаляет комнату и закрывает соединения.
- Завершённые партии и прерванные согласованной новой игрой записи попадают в локальный архив участников. Серверная история нужна только для синхронизации/отмены, обучения и аналитики нет. Локальный режим и бот по-прежнему не отправляют ходы на сервер.

## Локальная проверка

```sh
npm install
npm run dev
npm test
npm run test:rooms
```

Игра: http://localhost:8080/. `npm run dev` запускает Node-сервер исходников и локальный Wrangler на 8787. Node проксирует `/api/rooms*` и WebSocket upgrade. Если 8080 уже запущен отдельно, можно запустить только `npm run dev:rooms`.

`npm run test:rooms` требует работающего локального сервера. Проверяет реальными WebSocket-клиентами создание, вход, синхронизацию, очередь хода, согласованную отмену, восстановление, сдачу, новую партию и отсутствие ключей в публичном снимке.

Для проверки двумя браузерами на одном компьютере используйте разные профили или разные origin: создатель на `localhost:8080`, гость на `127.0.0.1:8080` с тем же `room` в URL. Две вкладки одного origin разделяют ключ места и считаются одним игроком.

Для проверки локальной игры на другом устройстве в той же сети нужен доступ к IP компьютера на 8080; `localhost` в приглашении следует заменить этим IP. Продакшен-ссылки используют текущий HTTPS-домен и не требуют этой замены.

## Публикация

Обычный процесс: локальная проверка → одобрение → push → существующий Cloudflare Workers Build. `wrangler.jsonc` добавляет Worker entrypoint, binding ROOMS и SQLite-миграцию `game-rooms-v1` (`new_sqlite_classes`). Не меняйте имя класса/тег опубликованной миграции и не используйте legacy-KV storage на Free. Оплата, DNS и домен не меняются.

Выполнено `wrangler deploy --dry-run`: Worker собирается, распознаны GameRoom и ASSETS. Это не подтверждение фактического деплоя в аккаунт.
